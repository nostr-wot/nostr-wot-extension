# Archive

Archive keeps an encrypted local copy of signed Nostr events for an account. It is available in Settings → Archive. It stores events, not recovery phrases or private keys; export your recovery material separately. Browser storage can be removed or evicted, so keep an archive file outside the browser when you need an independent copy.

## Using Archive

Configure Archive in Settings → Archive. Manual sync is always available; Automatic archive optionally runs hourly, daily or weekly. You can change the schedule, pause work, see progress and relay errors, and clear local archived events after confirmation. Watch-only accounts need an existing vault to encrypt the archive. Account onboarding does not prompt for Archive.

Archive actions use a compact icon row: sync (pause during active work), download, import and clear local archive. Each icon has a tooltip and accessible label; clearing still requires confirmation. The settings icon beside Sync opens Archive settings; Migrate archive is a separate labeled section.

All selected relays start concurrently, sharing the same encrypted archive. Each relay processes its own event streams and checkpoints independently, so a slow relay does not delay the others. Database commits serialize record/source merges by event ID; duplicate events do not create additional records, and unchanged records from the same source are not re-encrypted. Relay counters still include verified events already stored. Unsupported reconciliation can still cause duplicate network transfers; the local archive remains deduplicated. Active work continues between bounded slices without waiting for the next alarm; the alarm recovers work after actual worker suspension.

The first sync starts at the beginning of the account's available relay history. When supported, NIP-77 reconciliation compares bounded sets of event IDs before fetching missing events; unsupported or incomplete reconciliation falls back to time-based pagination. Later syncs revisit a seven-day overlap before the last completed checkpoint, and periodically reconcile history again. Relays may have discarded old events or impose undisclosed query limits: completing a relay query does not prove that every event the account ever created is available. Partial or failed relay queries retain valid events without advancing their coverage checkpoint.

The relay list starts with your configured relays. Open **Archive settings** to add or remove relay URLs. Removing every relay leaves the list empty and turns off automatic archiving; add a relay before syncing again. **Archive settings** contains the relay group picker and encrypted-message collection option. The picker marks **Profile relays (default)** and offers **Create new group**, which opens a dialog with a name and relay editor. The plus button opens an input with suggestions from common and previously configured relays, excluding relays already in that list; valid custom WebSocket URLs are accepted. Each relay appears on its own removable row. To start over, clear the local archive after confirmation and sync again. **Use profile relays** replaces the selected group with the account's published NIP-65 relay list and NIP-17 message relay list. Only the selected group's relays are queried. Encrypted message archiving includes authored and recipient-addressed NIP-04 events and NIP-59 gift wraps. Messages stay encrypted; Archive does not unwrap messages or export plaintext conversations.

Archive automatically answers valid NIP-42 challenges when a selected relay requires authentication for sync or migration. During sync, a relay AUTH challenge is answered directly, without requiring a separate CLOSED response; pre-authentication empty results do not count as completed coverage. NIP-77 discovery falls back to the authenticated reader when challenged. The transport waits for the relay’s acknowledgement before retrying the original request once, including when a read challenge arrives after the authentication-required response. Refusals, missing challenges and timeouts still stop that relay query; no validation is bypassed. This is separate from website authentication permissions. Local signing does not extend the vault's automatic-lock timer. A remote signer must already be connected for the active account; automatic archiving never creates a remote signer connection. Watch-only accounts can query public data but cannot authenticate to a relay.

After sync, a compact status distinguishes Complete, Incomplete, Error and Not synced. Incomplete is red when errors prevented full coverage and yellow when coverage is unfinished without an error; attempts that failed without fetching anything show Error. A relay succeeds only when every requested event stream completed. **See details** opens one result per relay with repeated errors shown once; **Change relays** opens Archive settings. Each unsuccessful relay has its own retry icon. Other relay buttons remain available; additional requests are queued, deduplicated and resumed after the current job, with Running or Queued shown per row. Pause or clear removes queued retries. Each retry queries only that relay, resumes unfinished checkpoints, retains every stored event and leaves other relays’ checkpoints unchanged. Events are merged by ID, so retrying does not duplicate or delete existing records. Events already saved remain available when another relay fails.

## Export and import

**Download archive** downloads ordinary signed events as `.ndjson`, one JSON event per line, without a file password. Private messages retain their protocol ciphertext; private keys and local relay metadata are not exported. **Import** accepts signed-event NDJSON for the selected account, checks ownership and signatures, then merges only after the complete input has been validated. Duplicate IDs do not create extra records. Old password-encrypted exports remain readable, with a password field shown only when such a file is selected. Both dialogs mount above the full popup rather than inside the Archive card.

A file export holds a stable local archive while generating its chunks. File operations expire after ten minutes and stop when the vault locks. Files and local archives are bounded at 512 MiB; browser quota may be smaller. Export is chunked over extension RPC, but the popup assembles the download in memory. If a storage failure or lock interrupts the final import merge, already merged valid events remain; retrying the file safely deduplicates them.

## Migrate archive

**Migrate archive** appears as a separate section once the local archive contains events. Enter a destination relay, review the eligible and skipped counts, then confirm. Migration does not delete the local archive or events on other relays. It republishes original signed events without changing timestamps, content, signatures or account identity. The extension records relay acknowledgements and distinguishes accepted, already present, failed and skipped events. After every eligible event has been attempted, migration makes one additional pass that retries only failed events. Successful retries update the accepted or already-present count and remove the failure; events already accepted are not republished. The retry cursor survives worker suspension. **Failed events** opens a popup with each remaining event’s ID, kind, date, relay response and attempt count, with a copy action for its ID. An interrupted request may be retried with the same event ID; this does not create a newly signed duplicate.

Deleted, expired and superseded replaceable events are skipped. Authentication events, ephemeral events and unwrapped private-message rumors or seals are never copied. Encrypted messages and unrecognized event kinds require separate opt-ins. Copying encrypted messages exposes their envelopes to the destination relay, even though their contents remain encrypted. Copying a previously unknown event kind may trigger behavior understood by its readers; review that choice before enabling it.

## Implementation

`domain/archive` owns settings, query ranges and eligibility policy. `services/archive` owns encrypted IndexedDB storage, resumable sync, file transfer and copying. `services/relays/transport.ts` multiplexes finite subscriptions and publish acknowledgements on leased relay connections; independent callers release only their own subscriptions. Authentication connections are scoped by account, vault revision and authentication mode. Public relay consumers can reuse anonymous connections within the background context; NWC and NIP-46 protocol sessions remain independent.

The `nostr-wot-archive` IndexedDB database encrypts signed event records and replacement/deletion indexes with the vault's private-cache key using account-specific authenticated data. Minimal metadata—account ID, event IDs, byte/count totals, relay URLs, checkpoints and progress—remains available without decrypting event bodies. Records are deduplicated by account and event ID. Checkpoints advance only after committed event batches. Per-relay, per-stream coverage prevents one failing relay from being hidden by another successful relay.

A browser alarm resumes bounded work after service-worker suspension. Durable job cursors survive interruption; automatic work waits for an unlocked vault. Lock, vault session changes and explicit pause cancel active operations. File transfers and copy operations share the same account-level exclusivity boundary as sync. Vault destruction clears the archive database and its settings.

Archive file version 1 uses AES-256-GCM and PBKDF2-SHA-256 with 600,000 iterations and a fresh 32-byte salt. Key derivation happens once per file session. Authenticated chunk ordering and a final authenticated footer detect tampering, missing chunks and truncation. Import stages ciphertext and validates the complete file before the merge. Existing signed event fields are preserved and signatures are checked; decrypted vault keys and account secrets are never part of the file.

All `archive_*` RPCs are restricted to internal extension pages by the background privileged-handler map. Websites cannot start sync, export files, change relay groups or publish an archive through the NIP-07 bridge.

The main Archive card omits the last queried URL, fetched count and large warning banner. Relay details show the total archive data size and a table with Relay, Events and Result, plus individual retries. Failed relay names and errors use the error color. Fetched counts track validated events obtained during the latest attempt, including events already stored locally; storage still deduplicates by ID. Older runs without counters show a dash. Archive size measures serialized archived data, not browser database overhead. Other relays’ results are retained when retrying one relay.

Sync shows a loading indicator while relay work is running. Saved-event counters and database size refresh after each committed batch, with per-relay counts in See details. Every active relay is shown as syncing before its reconciliation begins; a retry requested during another job is shown as queued. Migration results refresh after each processed event. Counters describe fetched events, including duplicates, rather than a percentage of unknown relay history.

Relay details keep error messages behind an information icon. Queued and running retries use the accent color; completed relays turn green, errors red and incomplete results yellow. Counts, loading indicators and error details update from the current sync result without reopening the screen.

Open Archive settings using the settings icon beside Sync inside the archive card.

Relay event counts include events already present locally, including matches confirmed by NIP-77 reconciliation. The archive total remains deduplicated. Incomplete means at least one requested stream did not finish; receiving one event does not establish complete coverage. Older results without saved counters remain unknown until another sync.

Migration suggestions reuse the same default relay constant and configured groups as Archive settings. Custom URLs must pass WebSocket URL validation. A bounded Nostr query must finish before the confirmation opens, and the destination is checked again before publishing begins. This checks protocol responsiveness, not whether the relay will accept every event; publication acknowledgments remain authoritative.

Recoverable authentication failures receive up to three bounded attempts on fresh account-scoped connections, retaining verified partial results. The relay details retry action becomes Re-authenticate and retry for these errors. Authentication failures remain stored with the checkpoints until the affected stream succeeds. Relay configuration errors such as a missing serviceUrl are not retried automatically; they require a fix by the relay operator. Authentication-required responses wrapped in `ERROR:` still trigger authentication, and the final acknowledgement determines whether the query can continue.

Migration verification requests at most one public profile event using an ordinary Nostr filter. It requires the relay to finish the query and never publishes a test event; an artificial epoch cutoff is avoided because some relays leave that query unanswered.

The Migrate archive card contains its own live status, result counters and pause control. Start migration verifies the destination and opens the event-count confirmation before publishing. The upper card continues to show relay sync results.

Plain imports are sealed with a fresh, session-only AES-GCM key before temporary staging in IndexedDB. The staging chain is checked before merging, so event bodies remain encrypted locally. Ordinary NDJSON has no authenticated end marker: invalid or partial JSON is rejected, but a file ending between valid event lines is a valid subset. Legacy encrypted files retain their authenticated header, chunk-order and footer checks.

## Event explorer

The Explore events icon opens a full browser tab when the current account has archived events, including a partially synced archive. Search public content, cached profile names, public keys, tags, event kinds and source relays. Above the table, All, Notes, Messages and Others tabs narrow the results; Likes, Reposts and recognized kinds have horizontally scrolling tabs. Tabs only appear for kinds present anywhere in the current account’s archive, independently of the search text. Public chat and encrypted formats share Messages, with format choices beside search. Public content appears directly; only encrypted formats have decryption controls. Others includes only unrecognized kinds. All and Others show generic event metadata, Notes shows content, and Messages shows From and To columns and blurred placeholders that decrypt inline when clicked. Decrypt all reveals messages on the current page, with individual failures shown per row. Search and type-specific filters sit together below the tabs. Profile shows all fields from the latest saved profile in a card; Contacts shows the latest saved contact list with cached identities and its update date, rendering 40 contacts at a time with Show more. Contact searches read existing cached names in bounded batches without relay lookups. Relay List shows its latest saved read/write relay settings and update date. Older versions remain accessible under All; Messages also filters the encrypted message format, and the kind field accepts unrecognized kinds. Search scans encrypted records in bounded batches. The archive total counts unique stored events; the matching count covers the entire filtered archive, separately from the current page of up to 40 events. Scan progress appears only while searching. Previous and Next browse in stable event-ID order. Private message bodies are not indexed or searched as plaintext.

Open an event for its readable preview, cached sender and recipient profiles, or its Advanced tab containing the original signed JSON, saved time and source relays. Profile display reuses the public profile cache without requesting contact metadata from relays. Clicking a blurred message decrypts supported private messages only on request with the selected account’s locally available key; remote-signer and watch-only accounts retain the encrypted view. Gift-wrap sender identity comes from the verified inner seal, not its temporary outer public key. Plaintext is not saved in a search index and the explorer clears when the vault locks or the account changes.

Select events and confirm Delete to remove those records from this device’s archive. The screen stays open and updates its results. Sync and migration pause before removal; no deletion event is published to a relay. Future imports or syncs can retrieve the records again. Replacement and deletion policy indexes remain intact so removing history does not make older or revoked events eligible for migration.

New records store numeric relay references into an encrypted, account-specific relay dictionary. Duplicate events merge every observed source. Version-one records remain readable and adopt the compact representation on their next write. Dictionary updates and event writes commit atomically. Imported events without recorded provenance display an unknown source; the explorer never guesses their relay.

App-specific data (kind 30078) and ephemeral events, including HTTP and relay authentication, are excluded from sync, storage and migration. Imports containing these events are rejected before committing any records, including legacy encrypted imports.

Decrypted message text stays in the current explorer view and is discarded on navigation or vault lock; it is not written to a search index. Bulk decryption is limited to the displayed page. Event text and profile fields render as text, not HTML. Profile names reuse local metadata caches, but avatar and banner URLs may still load images from external servers.

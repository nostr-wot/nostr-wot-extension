# 0.8.21 security review

Reviewed on 2026-11-02 against published 0.8.20 (`2137851`), covering PR #57 through release-preparation commit `7a784f8` and the corrections described below. This is a source and automated-test review, not an independent penetration test or a guarantee of security.

## Confirmed findings and corrections

### Medium: a template connection could undo a concurrent disconnect

Template connections read the connection list before writing permission rules and connection state together. A disconnect in another extension window could complete its storage update during that interval, after which the template operation restored the stale connection list. This could retain identity access that the user had revoked.

Connection templates, connection-list edits and identity toggles now share a mutation lock. Operations that also edit signing permissions acquire the site-consent lock first to keep lock ordering consistent. A regression test pauses a template connection, disconnects another site, and verifies that the disconnected site remains disconnected. The test failed before the correction and passes afterward.

### Medium: an older graph approval could override a newer denial

A graph request checked its permission before opening approval, but did not check that permission again after the user responded. If another window changed the rule to Deny while the approval remained open, approving the older request could still return graph data.

Graph requests now recheck Deny after approval and after the asynchronous graph query, before returning its result. Account-session cancellation is checked after those asynchronous permission reads. A regression test queues a request, changes its permission to Deny, then accepts the old approval; the request must reject. The test failed before the correction and passes afterward.

## Other boundaries reviewed

- Privileged recovery, export and template methods are restricted to extension pages. Website-facing methods use the browser-verified request origin.
- Template rules have bounded input, an allowlist of supported actions, exact-origin recommendations, active-account checks and preservation of existing denials. Recommendations do not grant access by themselves.
- Authentication groups retain site, account and protocol boundaries. Overview approval is one-time and snapshots the selected request IDs; later requests are not silently included. Wallet, zap and legacy login requests retain separate review.
- Key exports require an unlocked vault and retain session-change checks. Key inventory responses contain metadata, not secret material. Plaintext downloads are explicitly identified as unencrypted exports.
- Compact provider recovery contains the associated seed and derivation information or private key, encrypted using the existing authenticated-encryption path. It does not serialize unrelated accounts. Imported independent post-quantum keys retain the full-file fallback instead of silently disappearing from recovery.
- Provider writes check the 2 KB limit before attempting storage. Existing full-file and legacy provider recovery remain supported, and restored identities are checked against the credential's recovery public key when present.
- Relay recovery remains encrypted and verifies the signed event and recovery format before use. No new relay publication is authorized by merely viewing the settings.

No additional critical or high-severity issue was identified in the reviewed changes. This statement is limited to the scope and techniques above.

## Verification and limits

The focused suite covering permissions, domain consent, graph requests, authentication, RPC boundaries and passkey recovery passed 525 tests. Type-checking and lint passed. The production dependency advisory audit reported zero known vulnerabilities; this does not establish that dependencies are vulnerability-free.

Real passkey-provider synchronization, hardware prompts, cross-device blob availability and browser-store packages were not exercised by this review. Those remain part of the release walkthrough. This review does not authorize publication.

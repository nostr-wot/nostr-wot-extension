# Nostr WoT Extension 0.8.21

Release date: 2026-11-02.

## Release contents

- Optional site permission templates, custom templates, exact-origin recommendations, and the Nostr WoT Playground graph permissions.
- Security → Keys & Backups, compact passkey provider recovery, existing backup compatibility, and plaintext or encrypted key export.
- Grouped relay authentication, compact selection with Select all, one-time overview actions, and shared larger checkboxes.
- Six translated interface catalogs and updated recovery, permissions, and component documentation.

## Reviewer walkthrough

1. Connect nostrwot.com from the main card and globe menu. Confirm that the Playground template is suggested, template details open separately, and Skip retains existing global defaults.
2. Create and edit a custom template. Confirm its name and rules persist and edits do not retroactively change connected sites.
3. Open Security → Keys & Backups for seed-derived, imported-key, and passkey accounts. Check grouped key inventory and the appropriate reveal/export/recovery actions.
4. Save passkey recovery with a provider supporting largeBlob. Verify the compact payload fits the 2 KB limit and restores the same identity. Verify unsupported providers and independent imported PQ keys retain the full recovery-file fallback.
5. Queue relay authentication to several destinations. Check the grouped summary, selectable compact list, Select all, and raw-event popup. Approve only the selected requests; newly arriving requests must stay unchecked.
6. Check the pending overview’s plain Approve all/Deny all actions. Authentication approval reviews destinations once and does not store a persistent grant. Wallet, zap, and legacy login requests retain separate review.

## Publishing after approval

Follow [deployment](../deployment.md), [Chrome publishing](../chrome-publishing.md), and [Firefox publishing](../firefox-publishing.md). Run the required checks on the final reviewed commit, build and verify both browser packages, and retain their hashes and source archive. Use tag `v0.8.21` and release title `Nostr WoT 0.8.21`; use the store release notes from CHANGELOG.md.

Do not create the tag or GitHub release until explicitly approved. Publishing a stable GitHub release triggers Chrome and Mozilla submissions; verify each workflow and store status afterward. Store approval is separate from submission. Safari requires its separate wrapper build and submission process.
